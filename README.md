# سالن زیبایی کیمیا | KimiaBeautySalon

این ریپو محل اصلی کد سایت، پنل مدیریت، بک‌اند و مستندات کیمیاست.

**ریپوی اصلی:** https://github.com/amirfassadi/KimiaBeautySalon  
**سایت فعلی:** https://kimia-beauty-salon.miranco-projects.chatgpt.site

## شروع در VS Code

Node.js 22 یا جدیدتر و npm نصب باشد:

```bash
npm ci
npm run dev
```

پیش‌نمایش روی http://localhost:3000 است. نیازی به نصب Bash نیست.

```bash
npm run build
npm test
npx tsc --noEmit
```

ساخت نهایی در `dist/server/index.js` یک Cloudflare Worker است؛ خروجی ساخت را به Git اضافه نکنید. `npm run preview` هم پیش‌نمایش توسعه را اجرا می‌کند، نه میزبانی تولید.

## فایل‌های اصلی

| مسیر | کاربرد |
| --- | --- |
| `src/index.html` | سایت عمومی فارسی، خدمات، آتلیه و درخواست نوبت |
| `src/admin.html` | پنل مدیریت |
| `src/assets/` | تصاویر مفهومی طراحی؛ نمونه‌کار واقعی نیستند |
| `worker/` | مسیرهای سرور، نمایش صفحات و اتصال API |
| `db/migrations/` | ساختار نسخه‌بندی‌شده PostgreSQL |
| `scripts/vite-preview.mjs` | رابط اجرای محلی برای طراحی |
| `.openai/hosting.json` | شناسه و تنظیمات سایت موجود |
| `docs/OPERATIONS.md` | راه‌اندازی تولید و محدودیت‌ها |
| `docs/CONSOLIDATION.md` | منشأ فایل‌ها و نتیجه یکپارچه‌سازی |
| `archive/KimiaBeauty/` | نسخه قبلی سایت و مستندات SmartCore، فقط برای مرجع |
| `archive/history/` | تاریخچه قابل بازیابی ریپوی قدیمی و سایت |

## وضعیت قابلیت‌ها

- در لانچ معرفی، بازدیدکننده خدمات، نمونه‌کار و راه‌های تماس را می‌بیند؛ فرم درخواست/پیگیری نوبت و عضویت مشتری در رابط عمومی نمایش داده نمی‌شوند. کد و جدول‌های نوبت برای مرحله بعد حفظ شده‌اند.
- درخواست زمان پیشنهادی، نوبت قطعی نیست؛ تأیید نهایی توسط سالن انجام می‌شود.
- پیش‌نمایش محلی عمداً دیتابیس و هویت مدیر میزبانی‌شده را فعال نمی‌کند؛ ذخیره اطلاعات مشتری یا ورود جعلی وجود ندارد.
- احراز هویت مشتری فعلاً کاملاً غیرفعال است و UI فقط پیام «به‌زودی» نمایش می‌دهد. Endpointها و migration آزمایشی در کد باقی مانده‌اند، اما migration 004 و OTP/SMS/session در production فعال نیستند.
- دیتابیس موردنیاز PostgreSQL است. اتصال فعلی تولید از Supabase/PostgREST استفاده می‌کند. برای PostgreSQL مستقل، لایه اتصال مناسب لازم است.
- فعال‌بودن تولید به اجرای migrationها و تنظیم محرمانه اتصال وابسته است؛ وجود کد، تأیید اتصال واقعی نیست.
- قیمت خدمات، پرداخت آنلاین، ارسال پیامک و رابط کامل انگلیسی در این پیاده‌سازی فعال نیستند.
- تصاویر موجود مفهومی‌اند و با تصاویر واقعیِ دارای مجوز جایگزین می‌شوند.

## PostgreSQL و تولید

سه migration به‌ترتیب اجرا شوند. مقادیر `.env.example` فقط نام تنظیمات را نشان می‌دهند؛ اسرار را به Git اضافه نکنید. برای Worker تولید، تنظیمات اتصال در محیط میزبانی ثبت می‌شوند.

ورود فعلی مدیر به هویت تأییدشده Sites وابسته است. انتقال به میزبانی دیگر نیازمند احراز هویت معتبر جایگزین است. راهنمای کامل در `docs/OPERATIONS.md` است.

سایت فعلی و دسترسی آن در این یکپارچه‌سازی تغییر نکرده‌اند. Sites برای انتشار، مخزن داخلی مدیریت‌شده خود را نگه می‌دارد؛ مرجع توسعه دستی فقط این ریپوی GitHub است.

## معماری و آرشیو

طرح SmartCore از ریپوی قدیمی حفظ شده است. کد فعلی یک پیاده‌سازی مستقل سالن است و نباید ادعا شود اکنون به SmartCore متصل است. مستندات آرشیو نقشه راه و سابقه تصمیم‌ها هستند؛ دستور اجرای فعلی یا الزام ساخت هم‌زمان ماژول‌های آینده نیستند.

برای انتشار یا توسعه، از `src/` و `worker/` استفاده کنید، نه `archive/KimiaBeauty/web/`.
